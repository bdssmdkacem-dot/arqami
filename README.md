# أرقامي (Arqami)

تطبيق Flutter تعليمي للرياضيات باللغة العربية، من **3 إلى 16 سنة**. تحوّل المشروع من نموذج تعلّم الأرقام إلى **منهج من 52 وحدة** مع دروس، أنشطة تفاعلية، Quiz، Assessment، نجوم، وتقدم محلي.

> **الحالة الحالية — 17 سبتمبر 2026:** تثبيت المنهج ومحرك الأنشطة والتقدم. نحن الآن في **التدقيق السلوكي العميق للأنشطة والبيانات** قبل الانتقال إلى إعادة تصميم خريطة الرحلة التعليمية.

---

## 🎯 الرؤية

أرقامي ليس تطبيق MCQ فقط. المسار المستهدف لكل وحدة هو:

**تعلّم المفهوم → مثال → نشاط تفاعلي → تدريب Quiz → Assessment → نجوم وتقدم → فتح الوحدة التالية.**

الهدف النهائي هو تحويل الوحدات الـ52 إلى رحلة لعب تعليمية واحدة، مع خريطة أصلية مستوحاة من ألعاب المسارات دون نسخ لعبة بعينها.

# 📚 المنهج — 52 وحدة

- **1–13:** الأرقام 0–10، العد، الكميات، التتبع، المقارنة، المراجعة.
- **14–20:** الآحاد والعشرات وبناء وتفكيك الأعداد حتى 100 والمقارنة والترتيب.
- **21:** بوابة مراجعة قبل المئات.
- **22–27:** المئات والقيمة المكانية وبناء وتفكيك الأعداد والمقارنة والترتيب.
- **28–33:** الآلاف والقيمة المكانية وبناء وتفكيك الأعداد الكبيرة.
- **34:** بوابة العمليات الحسابية.
- **35–40:** الجمع والطرح والتطبيقات والمسائل اللفظية.
- **41–46:** الضرب والقسمة والقسمة مع الباقي والقسمة المطولة والعمليات الأربع.
- **47–48:** مفهوم الكسور، البسط والمقام، التكافؤ والمقارنة.
- **49–50:** العمليات على الكسور والأعداد العشرية والقيمة المكانية والعمليات العشرية.
- **51–52:** النسبة، معدل الوحدة، التناسب، النسبة المئوية، التعبيرات، المعادلات والمتباينات.

مصادر المنهج:

```text
lib/models/units_data.dart
lib/models/final_curriculum_override.dart
lib/models/unit_model.dart
```

الوحدات ليست مجرد بيانات أسئلة؛ لكل وحدة بنية أنشطة مرتبة.

# 🎮 محرك الأنشطة

المشغل الرئيسي:

```text
lib/screens/unit_player_screen.dart
```

الأنواع المدعومة:

- Lesson
- Multiple Choice / Quiz
- Review
- Assessment
- Arithmetic
- Word Problem
- Trace
- Matching
- Comparison
- Scene Explore
- Drag Count

ويتم تشغيل الأنشطة بالتسلسل حتى نهاية الوحدة، ثم فقط يتم تسجيل إكمالها في `ProgressTracker`.

### تدقيق سلوكي تم إنجازه

هذا التدقيق لا يكتفي بالتأكد من وجود نوع النشاط في الكود، بل يبحث عن حالات يكون فيها النشاط موجوداً لكنه لا يحقق الهدف التعليمي فعلياً.

تم إصلاح:

1. **Drag Count للصفر:** الوحدة 1 كانت تستخدم `targetCount = 0` بينما المحرك كان يتعامل عملياً مع العد ابتداءً من 1. أصبح الصفر حالة صالحة ويمكن إكمال النشاط.
2. **Comparison — التساوي:** `ComparisonQuestionType.equal` موجود في نموذج المنهج، وتم جعل `ComparisonWidget` يتعامل مع الكومتين المتساويتين كسؤال تساوٍ فعلي حتى لو وصلته إعدادات مقارنة غير مثالية. هذا يمنع فشل النشاط عند تساوي القيم.
3. **Assessment:** التقييم النهائي منفصل عن Quiz، ويحتاج **70%** على الأقل قبل إكمال الوحدة.

### ملاحظة تدقيق مهمة

تم العثور أيضاً على مشكلة **محتوى** في النشاط القديم للوحدة 15: كان Matching يربط `14 → 10` و`18 → 10`، وهو غير فريد ولا يختبر تفكيك العدد بصورة صحيحة. هذا ليس خطأ Widget بل خطأ في تصميم البيانات، ولذلك سيُعاد بناء هذا النشاط كتمرين تفكيك/بناء حقيقي بدل الاحتفاظ بمطابقة مضللة.

هذه النقطة جزء من التدقيق الحالي وليست مجرد اختبار شكلي.

# 📝 Quiz وAssessment

### Quiz

تدريب أثناء التعلم، ويمكن للطفل التعلم من الخطأ والمحاولة مجدداً.

### Assessment

تقييم نهاية الوحدة:

- يسجل الإجابات بالترتيب.
- يحسب النتيجة.
- حد النجاح: **70%**.
- عند الفشل تسجل محاولة ويعاد التقييم.
- لا تُعتبر الوحدة مكتملة من Assessment فاشل.

المحرك:

```text
lib/core/assessment/assessment_engine.dart
```

# ⭐ التقدم

```text
lib/core/progress/progress_tracker.dart
lib/core/progress/unit_progress.dart
```

التقدم محلي باستخدام Hive.

القواعد:

1. الوحدة 1 مفتوحة دائماً.
2. لا تفتح الوحدة التالية قبل إكمال السابقة.
3. لا يمكن تخطي وحدة.
4. أفضل عدد نجوم محفوظ.
5. المحاولات الفاشلة مسجلة.
6. إكمال الوحدة يعتمد على اجتياز مسار أنشطتها والتقييم النهائي.
7. يمكن حساب التقدم من أصل 52 وحدة.
8. إكمال جميع الوحدات = 100%.

للاختبارات، يدعم `ProgressTracker.init()` مسار Hive اختياري حتى لا تعتمد الاختبارات على `path_provider`.

# 🎨 استراتيجية الأصول والتصميم

تم اعتماد نظام أصول موحد لتجنب خلط مكتبات بصرية كثيرة.

المصدر الأساسي المخطط له هو **Kenney CC0**:

- الشخصيات: Roguelike Characters.
- العالم والخريطة: Tiny Town.
- الواجهة: UI Pack.
- أصوات الواجهة: UI Audio.
- الأيقونات عند الحاجة: حزم Kenney المناسبة.

وتستخدم أصول **Tiddybub 2D Assets** بشكل انتقائي للمؤثرات فقط عند الحاجة.

هيكل الأصول المضاف للمشروع:

```text
assets/
└── game/
    ├── characters/
    ├── backgrounds/
    ├── ui/
    ├── numbers/
    ├── rewards/
    ├── effects/
    └── sounds/
```

تمت إضافة البنية وسياسة المصدر والتتبع، **ولم يتم نسخ مكتبات الأصول كاملة إلى المستودع**. سيتم إدخال الملفات المستخدمة فعلياً فقط.

### التكيف حسب العمر

نفس الهوية الأساسية للأصول، مع تغيير الحجم والكثافة والحركة ومستوى التحدي:

- **3–5:** أرقام كبيرة، شخصية واضحة، تحكم بسيط، عد وسحب.
- **6–9:** مستويات ونجوم وXP، جمع وطرح، عشرات ومئات.
- **10–12:** واجهة أقل طفولية، ضرب وقسمة ومسائل متعددة الخطوات.
- **13–16:** عرض أنضج وتحديات أصعب وتطبيقات عملية وجبر.
